# LCD: Sitronix ST7920

Model: `src/hw/st7920.rs`, as on the common 128x64 "12864" modules.
Datasheet: Sitronix ST7920 V4.0 (2008-08-18), the English one. All figures
below are from it, at VDD = 4.5-5.5 V.

## Module pins

| Pin | Name | Model |
|---|---|---|
| 4 | RS (CS in serial mode) | `RS` |
| 5 | R/W (SID) | `RW` |
| 6 | E (SCLK) | `E` |
| 7-14 | DB0-DB7 | `DB0`-`DB7` |
| 15 | PSB: high parallel, low serial | `PSB`, high when open |
| 17 | RST, low active | `RST`, high when open |

PSB and RST read high when nothing drives them, as the modules pull them
up. The power, contrast and backlight pins aren't modelled.

## What the model does

- **Bus:** 8-bit and 4-bit parallel (Function Set's DL) with PSB high, and
  the serial bus with PSB low. Writes are taken when E falls. A read drives
  DB0-DB7, or DB4-DB7 in 4-bit mode, while RW and E are high. In 4-bit mode
  the high nibble goes first, for writes and reads. The serial bus has no
  reads, like the chip: a sync of five 1s, then RW and RS, then each byte
  as two groups of four bits followed by four 0s.
- **Busy flag and execution times:** 72 us per instruction and per data
  byte, 1.6 ms for Display Clear, at fosc = 540 kHz. `fosc=` (470 to
  600 kHz) scales these times. BF is 1 meanwhile, and anything written in
  that time is ignored and reported, as the datasheet says the chip won't
  take it. So are writes in the first 40 ms after power-on, and anything
  while RST is low. RST going high restores the initial register values.
- **Instructions:** the basic and the extended set. Function Set follows
  the datasheet's rules: DL and RE can't change in one instruction (only DL
  does), and G only changes while RE is 1 and stays 1. So `0x34` then
  `0x36` turns graphics on, `0x36` sent from the basic set doesn't, and
  `0x30` returns to the basic set with graphics still on. Set GDRAM Address
  is two writes, vertical then horizontal. Also emulated: Display Clear,
  Return Home, Entry Mode (I/D), Display Control (D), cursor moves, Set
  CGRAM/DDRAM Address, Standby, Reverse, and Scroll or RAM Address Select.
- **Reads:** BF and AC with RS = 0. RAM reads with RS = 1 need a dummy read
  after an address is set or data is written, as the datasheet says.
- **RAM:** DDRAM (64 words), CGRAM (4 characters of 16x16) and GDRAM (64
  rows of 256 bits) hold random contents at power-on, as a real chip does.
  Firmware has to clear what it shows.
- **Display:** the 128x64 panel shows the top 32 rows of a 256-wide plane
  folded in two. Plane columns 0-127 go on rows 0-31 and columns 128-255
  on rows 32-63. So GDRAM words 0-7 of rows 0-31 are the top half and words
  8-15 the bottom half, and DDRAM lines 0x80, 0x90, 0x88 and 0x98 are the
  four text rows. The text layer (half-width characters and CGRAM
  characters) is XORed with the graphics layer when G is on. D off or
  standby blanks the panel.
- **Bus timing:** E cycle TC 1200 ns, E pulse TPW 140 ns, address setup
  TAS 10 ns, data setup TDSW 40 ns, and on the serial bus a 400 ns SCLK
  cycle and 200 ns high and low times. A violation is reported, and the
  transfer still happens.

Each kind of problem is printed on stderr the first time it happens.
`Component::warnings()` counts all of them, and the Tetris and TinyStories
tests check that it stays 0.

## What it doesn't do

- The 16x16 CGROM (Chinese) characters, the cursor, blinking, display
  shift and vertical scroll are reported when used, but not drawn.
- The half-width font is the X11 8x13 font (public domain) in 8x16 cells
  (`tools/st7920_font.py`), not the chip's HCGROM. Character codes
  0x02-0x1F, which the HCGROM has, show blank.

## Choices where the datasheet is silent

- The first byte of a 16-bit data word takes 72 us like any other write.
- Display Control's D switches the whole display, graphics included.
- BF/AC reads give the horizontal address as AC while GDRAM is selected.
- Any instruction between the two Set GDRAM Address writes starts over
  with the vertical address.
- Data lines that are open during a write latch as 0, and this is
  reported. Tie unused lines (DB0-DB3 in 4-bit mode) to GND.

## Bringing a module up

8-bit, from the datasheet: wait 40 ms, Function Set `0x30` twice, `0x0C`,
`0x01` (wait 1.6 ms), `0x06`. Then `0x34`, `0x36` for graphics.

4-bit: send the single nibbles 3, 3, 3, 2, waiting 160 us after each.
That reaches 4-bit mode from any state, including after the MCU alone
was reset halfway through a byte, when the busy flag can't be trusted yet.
Then use `0x20`, `0x0C`, `0x01`, `0x06`, `0x24`, `0x26` (DL stays 0), as
`boards/tinystories/fw_lcd.inc` does. The datasheet's own 4-bit
sequence, Function Set as two nibbles right after power-on, works in the
model too. The chip is still in 8-bit mode, so the first nibble is a whole
Function Set, and the second arrives while the chip is busy and is
dropped.

## The Tetris firmware

`boards/tetris/tetris.asm` is the original game with its LCD driver fixed
for a real ST7920. In the original, `LCD_Read` set TRISC without a bank
switch, so PORTC stayed an output. Every busy-flag read then saw the PIC's
own 0xFF, so the poll was only a delay. Once the bank switch was fixed, it
waited for BF = 1 forever. It also polled with RS = 1, which reads RAM
instead of BF, and sent the second data byte without waiting. The game
logic is unchanged.
